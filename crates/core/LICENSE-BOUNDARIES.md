Local Rust, JavaScript and Swift package scripts include both SDK license texts and a copy of this inventory boundary document. Package-local synthetic test fixtures and license files are generated from their canonical workspace copies by `scripts/sync-package-resources.py`; CI checks that they agree. The npm package contains compiled facade code plus WASM. The Swift package contains generated UniFFI bindings, the linked Rust XCFramework and original MIT OR Apache-2.0 `BookNookServices`/`CastaliaNative` Swift facades; the MPL application consumes these same source files. Downstream binary notices must cover the actual linked dependency closures as well as the new dual-licensed SDK code. The generic Castalia custody extraction introduces no new third-party dependency. A locally passing package/consumer test does not replace that distribution notice review.

The locked dependency inventory is [dependency-licenses.csv](DEPENDENCY-LICENSES.csv), regenerated by `python3 scripts/license-inventory.py` from `cargo metadata --locked --offline --all-features`; use `--check` to verify freshness without writing. The current inventory contains **328 Rust packages**, including four workspace packages. It covers the 322-package default graph and six additional packages selected by the optional binding-generator feature, as well as build tools and platform dependencies that may not ship. Enabling all features here is conservative inventory collection; it does not enable them in shipped binaries. Native Rust/Swift, iOS and WASM artifacts need a notice and license review of their actual dependency closure. The separately locked npm graph contains TypeScript 5.9.3 (Apache-2.0), a development tool. The Python reference companion uses the Python standard library and declares no third-party Python dependencies.

The metadata audit found no missing license expressions or `REVIEW REQUIRED` rows in the Rust graph. No AGPL package or GPL-only expression appears in that locked Rust graph. The separately installed optional Python account adapter is covered below. These are inventory results, not a legal compatibility determination. Review these specific boundaries before distribution:

- UniFFI and its runtime/generator crates declare MPL-2.0. The new SDK source remains dual-licensed; that does not change UniFFI's license.
- `r-efi` declares MIT OR Apache-2.0 OR LGPL-2.1-or-later. Record the selected alternative in distribution notices.
- `ring` declares Apache-2.0 AND ISC; `unicode-ident` declares (MIT OR Apache-2.0) AND Unicode-3.0. The `AND` terms must remain visible in notice review.
- `webpki-roots` declares CDLA-Permissive-2.0 for its certificate data. ICU and related Unicode data crates declare Unicode-3.0. Include data-license review alongside code licenses.
- Several upstream packages use legacy slash notation such as `MIT/Apache-2.0` and `Unlicense/MIT`. The CSV preserves these declarations verbatim; resolve them from the packaged license files when creating notices.
- FFI packages can contain separately licensed bundled source, including SQLite and cryptographic libraries. Cargo metadata is a starting point for that source-level review.
- Apple SDK frameworks are system dependencies governed by their own terms and are not relicensed or vendored.

Castalia Filesystem and the unofficial Audible Python implementation are not linked into the native app or Rust/Swift/WASM SDKs. The original Rust experimental Audible boundary remains dual-licensed. A separate, explicitly installed optional Audible account process (source workspace: `services/optional-audible-adapter/README.md`) now uses `audible==0.10.0` (AGPL-3.0-only) and an OS keyring. That process has its own AGPL license text, pinned dependency inventory and upstream notices. Neither the app nor normal SDK build/package scripts install it automatically. Process separation describes the architecture; it is not a claim that combined distribution or network use is exempt from AGPL obligations. Review the optional component's actual distribution/use separately and preserve its corresponding source and notices.

The Castalia verifier, native custody adapter and optional reference issuer are original implementations of the inspected protocol, using declared Rust cryptographic dependencies. The public synthetic interoperability vector is documented in [the integration decision log](INTEGRATION-DECISIONS.md); it contains no user key material. The reference issuer's Rust binary is dual-licensed and its Python HTTP wrapper is MPL-2.0; it does not incorporate the upstream unlicensed producer implementation.

The inspected Castalia wallet core declares MIT. The adjacent presentation crate lacks explicit license metadata in the inspected source snapshot. It is **not a dependency of this build**, and its implementation was not copied. Obtain a clear upstream license before any future vendoring or redistribution of that crate. Its unresolved license does not block the independently implemented custody adapter in the current dependency inventory; upstream interoperability qualification remains a separate release check.

Standard texts are included at the root. [MPL's official FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) explains its file-level scope. The full graph inventory is an engineering record, not a claim that every possible future dependency or distribution channel has already been approved.

The native Kindle web connector source inventory (source workspace: `docs/kindle-web-source-inventory.json`) records its pinned MIT protocol/model reference and bundled notice (source workspace: `apps/apple/Resources/KindleWebSourceNotice.txt`). Its new implementation is MPL-2.0, links only Apple system frameworks, and does not include the AGPL virtual-device/DRM alternative. The Rust/npm dependency graphs are unchanged by that connector.

[0.14.1 LICENSE](https://raw.githubusercontent.com/ziglang/zig/0.14.1/LICENSE) declares MIT.
The distribution also contains LLVM and other component notices; LLVM documents its
[Apache-2.0 WITH LLVM-exception and retained legacy boundaries](https://llvm.org/docs/DeveloperPolicy.html#copyright-license-and-patents).
Linux builds may use separately installed LLVM clang/llvm-ar. These are build tools outside
Cargo metadata, not dependencies relicensed by Book Nook. The downloaded compiler tree
stays in the task's work directory and is not included in source archives or SDK packages.
Review any compiler-supplied runtime code actually incorporated into a distribution under
its own notices; compiler choice alone is not a blanket license approval.
