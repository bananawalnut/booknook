# Reusable native Castalia custody

`CastaliaNative` is a Swift product backed by the public Rust/UniFFI `CastaliaCustody` object. It can be used without `Desk`, SQLite, Book Nook settings, or a Book Nook account. Importing this product does not create an identity, confer application permissions, or provision an issuer.

Construct `CastaliaSession` with four host implementations:

- `CastaliaSecureMaterialStorage`: namespaced encrypted recovery storage. Failed replacement must preserve the previous item. `CastaliaKeychainStorage(service:accessGroup:)` supplies the native adapter; use an explicit service. Shared access groups require the embedding app's own configuration and entitlements.
- `CastaliaCurrentTrustPolicySource`: independently saved issuer pins, holder, audience, caller and policy digest. Its `CastaliaPolicySnapshot.generation` must change when privileged configuration changes. Call `policyDidChange()` immediately when replacing settings, even when they later return to an earlier value.
- `CastaliaAuthorityRequestSource`: obtain a Castalia generic v2 request credential for the exact canonical request and disclosure. This protocol does not assume any issuer HTTP API. A response never supplies or installs trusted pins.
- `CastaliaConsentPresenter`: display the prepared disclosure and return true only after a deliberate approval. `cancelConsent` must resolve any pending presentation; cancellation is never approval.

The application supplies its own operation schema in `CastaliaRequestIntent`. `canonicalRequest` uses the Rust canonicalizer and rejects duplicate JSON keys. `authorize` validates exact expected request bytes and disclosure, re-reads current independent trust after the issuer response and after consent, and returns the signed request/presentation pair. Lock, cancellation, failed unlock, expiry and configuration replacement invalidate pending preparations. Rust consumes a preparation token on every approval attempt, including a failed attempt. There is no raw-signing API.

Receivers must validate their own operation schema and permissions in addition to the generic Castalia proof, then atomically consume its replay key with the authorized mutation. Generic validation is not permission to execute a Book Nook command. Book Nook continues to require its `booknook.authorized-action.v1` contract, exact payload digest and resource version in the existing receiver paths.

`CastaliaRecoveryCandidate` and `CastaliaRecoveryImportSession` stage replacement in memory, use isolated validation, recheck configured identity and existing saved bytes, and commit only after explicit validation/save intent. The default account is `encrypted-recovery`; hosts can choose a separate account. Book Nook retains `org.booknook.castalia` and its existing account names. The encrypted recovery envelope, KDF parameters and Castalia signature domains are unchanged. Rust clears sensitive decrypted/key buffers using its existing zeroizing implementation; Swift strings do not offer a guaranteed memory-zeroization contract.

The installed-package acceptance consumer in `tests/PackagedCastaliaSmoke.swift` uses only public synthetic recovery/issuer data and in-memory namespaced stores. Generate its short-lived fixture immediately before running the compiled consumer with `cargo run --locked -p booknook-native --example castalia-fixture`; verify the resulting receipt using that example's `verify` mode. This proves generic second-app reuse and rejection behavior, not a deployed issuer, real user identity, cross-app Keychain entitlement, or live account qualification.

For an existing native host, keep issuer configuration and action creation in the host, move only recovery custody and consent coordination into `CastaliaSession`, and inject the current settings through the policy source. Keep the old receiver's action checks. Book Nook follows this migration: its coordinator supplies the existing issuer HTTP envelope and observable consent sheet, while `SecureStorage.swift` delegates to the shared adapter with the original namespace. Legacy `Desk.custody_*` methods remain available for source compatibility; the reference app now uses standalone custody.
