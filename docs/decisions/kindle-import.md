# Kindle metadata snapshot decision log

2026-10-11. Scope: extend required Kindle catalog import with a grounded current Mac cache format. Preserve release gates for real accounts, real source artifacts, Apple UI interaction and physical iPad acceptance.

- **Choose an explicit local snapshot.** The reader or operator selects the file. No cache path discovery, Amazon session/cookie handling, hidden registration or book-content/DRM access. A native raw-database upload is restricted to literal loopback; the companion independently requires an actual loopback peer and a loopback-bound server. Remote companions receive metadata-only normalized JSON exported locally.
- **Keep interchange compatible.** `booknook.kindle-catalog.v1` and its ASIN/title/authors fields are unchanged. The cache adapter always emits null position and source observation time. No new Rust/SDK schema, manifest capability or provenance sidecar was introduced. Source context is explicitly disclosed by the file-selection flow; existing imports preserve ASIN and normalized record evidence. The current contract does not encode a cache-source subtype.
- **Use documented metadata only.** Primary evidence is MIT [listKindleBooks2 commit 6e34d7b2e2ea58e77246166685b6bdc7e8152289](https://github.com/rok-git/listKindleBooks2/tree/6e34d7b2e2ea58e77246166685b6bdc7e8152289). The original Python parser reads `ZBOOK` display title and inert `SyncMetadataAttributes` ASIN/authors. It deliberately omits the upstream book-ID fallback, author-network lookups and unrelated columns. [Source evidence and full bounds](../../services/library-companion/SOURCE-EVIDENCE.md) include the upstream MIT notice and accepted archive layout.
- **Reject incomplete WAL images.** Raw WAL-mode headers fail, including after a simple app quit. Use SQLite's consistent backup operation, then switch only the backup to DELETE journal mode. No sidecar files are scanned or copied automatically. The real SQLite regression verifies a committed title in WAL survives this preparation and that an unprepared file is rejected.
- **Normalize before persistence.** Operator-selected SQLite is checked before serving and kept only as normalized metadata in memory. A successful HTTP upload atomically saves only normalized JSON. Standalone export starts no server and creates a new private mode-0600 file without overwrite. Invalid records fail the complete import and preserve the previous active catalog.
- **Honor the uploaded selection.** Review found the old source precedence could return A after the user uploaded B. A persisted successful upload now takes precedence over configured source files and live adapters across restart. To resume an operator-configured source, stop the companion and remove only its saved normalized `kindle-catalog.json` selection, then restart. Imported Book Nook books are unaffected.
- **Isolate optional adapter outages.** Missing/crashed/malformed optional providers no longer prevent pairing or remove working local Kindle capabilities. The closed manifest shape stays unchanged: only independently available local capabilities remain, `qualified` becomes false, and its display name carries fixed actionable outage text. Live routes return sanitized unavailable/invalid-source errors. Capability refresh probes again after repair. Capability subprocesses have a three-second deadline so the local fallback arrives before the native 25-second request timeout; account/source operations retain their 25-second deadline. A genuine hung-child regression verifies bounded fallback and fail-closed live routes. Genuine subprocess regressions cover configured and previously uploaded local sources.
- **Preserve text-format compatibility.** Existing JSON/XML inputs remain supported. BOM-marked UTF-8/16/32 XML is now decoded before DTD/entity rejection, matching the native upload guard. Unknown encodings/layouts are not inferred.
- **Do not claim cloud or progress integration.** Public primary exporters expose a Cloud Reader `kindle-library/search` catalog shape, but current firsthand implementations disagree about JSON versus embedded HTML delivery, and no authenticated target-marketplace response was available. This work therefore adds a current cache-format importer. It does not implement live Kindle login, prove complete purchases, or invent reliable reading positions from percentage/recency fields.

Verification uses an independent, checked-in binary archive generated by Apple's real Foundation `NSKeyedArchiver`, synthetic SQLite databases, actual loopback HTTP and subprocess CLI execution. The companion suite covers malformed and cyclic archives, classes/references/duplicate keys, schema and size bounds, omitted private fields, WAL backup, local-only raw handling, durable source replacement, failure preservation, 0600/no-overwrite output, and prior pairing/account workflows. No actual reader database or Amazon credential was used. Live source qualification remains required; synthetic contract coverage does not satisfy it.

Reproduce with `python3 -m unittest discover -s tests/companion -v` on Python 3.11+ with SQLite deserialize support. The loopback tests need local socket permission. Regenerating the Foundation fixture is optional and needs macOS; its source is in `tests/companion/fixtures/generate-kindle-metadata.swift`.

Final result: 19 companion tests passed, including 13 new snapshot/compatibility tests and the 6 existing pairing/account cases. Python syntax compilation also passed. This adds implementation evidence without satisfying the real-cache, real-account or hands-on Apple acceptance gates.
