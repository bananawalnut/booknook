# SDK packaging decisions

The completion audit tested whether SDK consumers could work from packages rather than from the reference application's checkout. No package registry, repository URL, Apple distribution account or remote publication was invented or used.

- Rust manifests now describe the packages, include README/license material, and version their local Book Nook dependencies. Test vectors referenced outside crate boundaries are mirrored into each crate by `scripts/sync-package-resources.py`; its check mode detects drift against canonical fixtures and ontology conformance records. The actual four `.crate` archives were extracted into a separate workspace and their tests/examples passed with explicit local patches for unpublished siblings. Cargo 1.96's built-in temporary-registry verification failed with an internal missing-hash error, so archive creation and independently executed verification are documented separately.
- The JavaScript package now contains compiled CommonJS and ESM, declarations, and separate browser/Node WASM runtimes. Builds no longer overwrite one runtime with the other. Export paths are explicit, and packing rejects missing runtime files. Installing the actual npm tarball into an independent consumer passed CJS, ESM, both WASM initializers and NodeNext type checking. That consumer test exposed and fixed an extensionless generated declaration import.
- Swift delivery is a standalone package with generated UniFFI source and an arm64 macOS/iOS-device/iOS-simulator XCFramework. Generated sources and binaries stay out of the source archive. The final package was regenerated from the matched release archives after all three Apple platform builds passed. Verification created the actual tarball, extracted it independently, checked headers/license files, and linked and ran a separate Swift consumer that persists and reopens a synthetic desk. Intel slices and code signing are not claimed.
- Archive verification refreshes extracted file timestamps before reusing compiler caches. The final Rust package check exposed Cargo reusing an older build because archive timestamps are normalized; refreshing the extracted copies forces verification of the new sources without modifying the archives. The Swift package consumer applies the same cache invalidation.
- Package scripts use workspace-local caches and temporary synthetic data. SwiftPM requires normal macOS manifest-sandbox access; the isolated consumer test was permitted to use it without interacting with the user application or simulator. The npm packaging cache stays under `target` and does not change permissions on the user's npm cache.
- Final user-facing packages are staged into `outputs/booknook-sdk` with integrity checksums by `scripts/stage-sdk-deliverables.py`. CI runs package/consumer verification only; it contains no publish operation. Source/build scripts remain the reproducible handoff, and binary/license review remains distinct from registry publication and physical/account qualification.

Commands and output paths are in [DEPLOYMENT.md](../DEPLOYMENT.md). Final verification passed on the frozen source: all four extracted Rust packages ran 106 tests with three intentional helper/opt-in ignores; the installed npm archive passed CJS, ESM, browser/Node WASM and independent declaration checks; the extracted Swift archive compiled and executed its separate consumer. Evidence is in `work/completion-final-package-rust.log`, `work/completion-final-package-typescript.log` and `work/completion-final-package-swift.log`. All six user-facing archives and integrity checksums are in `outputs/booknook-sdk`. The central validation record preserves these results alongside the remaining physical/account acceptance gates.
