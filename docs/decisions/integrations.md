# Integration decisions

These decisions were made while the owner stepped away and requested autonomous delivery. All account, issuer, trust and pairing settings are entered through Book Nook’s Connections interface; no passwords or keys were requested through chat.

| Decision | Reason | Consequence / review |
|---|---|---|
| Keep wallet possession, independently configured issuer trust, and per-action approval separate. | The inspected Castalia v2 contract requires all three. Rolodex and Nostr identities do not substitute for authorization. | A reader can work offline without signing. Sync/publication needs an unlocked configured holder and a fresh native consent sheet. |
| Implement native custody against the exact Castalia v1 recovery envelope, using standard cryptography libraries. | The inspected wallet core is MIT; its newer presentation dependency lacked a license declaration. Vendoring the full tree would create an unresolved redistribution problem. | The implementation uses the existing Argon2id 64 MiB / 3-pass / 1-lane parameters, AES-256-GCM authenticated header, NFC passphrase, Ed25519 PKCS#8 identity, and BLAKE3 key identifier. No weaker fallback or substitute signature exists. |
| Verify compatibility with the upstream public synthetic vector. | Self-round-trips alone would miss a recovery incompatibility. | The published RFC 8032 test identity recovers byte-for-byte; a new v2 receipt from that identity passes the independently implemented receiver. Fixture contains only published synthetic material. |
| Add `policy_digest` and `credential_endpoint` as optional-default configuration fields. | Existing connection files must remain readable, and the issuer endpoint must not be inferred from incoming credentials. | Older configurations still load. They require completion before authorizing an action. Endpoint tokens are stored separately in Keychain, bound to the exact configured endpoint. |
| Expire prepared approvals and consume them once. Lock on background or five minutes of inactivity. | An unlock is not a blanket permission to sign. Trust settings can change between preparation and approval. | Custody revalidates the current pinned policy, holder, caller, payload, resource version and expiry when approving. Cancellation, lock, failed unlock, expiry, and changed trust invalidate outstanding work. |
| Implement a paired, replaceable library companion contract and a local reference service. | Kindle and Audible do not provide a documented supported public personal-library API that was qualified for this build. | Book Nook can pair, revoke, query capabilities, launch a provider-owned authorization URL, refresh a Kindle catalog, and obtain normalized Audible observations. A separately installed source adapter supplies live account authentication/renewal. |
| Do not impersonate an official Audible client or embed an unofficial AGPL authentication library in the native app. | The documentation describes simulated device registration; it is not evidence of a supported public integration. Live credentials were unavailable and registering a device silently would violate the product’s consent model. | Built-in direct Amazon sign-in and live Kindle/Audible qualification remain release blockers. The app and companion return unavailable/denied honestly when the source adapter is missing or expired. |
| Accept a selected Kindle metadata XML or normalized JSON export as a real local data source. | Catalog access is independently useful without ebook bytes. Existing Kindle metadata cache exports contain ASIN/title/authors, not guaranteed progress. | The reference companion normalizes catalog metadata without synthesizing reading progress or retrieving protected content. Repeat imports preserve private personal edits through the Rust import path. |
| Keep audio and ebook locations distinct. | A percentage or time ratio does not establish edition alignment. | Positions retain source-update and fetch times and become stale after 15 minutes. The reader can explicitly confirm a suggested edition association; this never computes an ebook percentage or text position. |
| Allow HTTP only on exact loopback and disable redirects. | Companion and issuer tokens must not be forwarded to another host. | An iPad talking to a Mac needs an HTTPS companion with a trusted certificate. No Book Nook-operated server is required. |

## Implemented verification

- Rust native custody tests import the exact upstream Castalia custody-v1 vector, create a v2 presentation and verify it independently.
- Tests reject wrong passphrases, weaker KDF parameters, changed payloads, revoked issuer pins, expired approvals, reused tokens, and signing after lock.
- Core authority/settings tests pass after extracting the issuer-request validation stage and adding backwards-compatible fields.
- Companion tests exercise one-use pairing, expiry, revocation, real XML catalog normalization, missing live source behavior, duplicate-key rejection, and XML external-entity rejection.
- Position adapter tests preserve stale source timestamps and reject future evidence, invalid identities, and unsubstantiated edition matches.

## Evidence and limits

The exact recovery/vector evidence came from `castalia-wallet-core` at the locally inspected `ff8de6d` qualification snapshot, package license MIT. Its generic v2 contract was independently checked against the local `castalia-wallet-auth/docs/credential-presentation-v2.md`. No Castalia upstream source files or unlicensed presentation crate were bundled. The portable public fixture records provenance.

The [Audible authentication documentation](https://audible.readthedocs.io/en/latest/auth/authentication.html) and [device registration documentation](https://audible.readthedocs.io/en/stable/auth/register.html) describe a non-public integration. The [last-position endpoint documentation](https://audible.readthedocs.io/en/latest/misc/external_api.html) does not specify a trustworthy source timestamp response shape. The companion therefore requires its source adapter to normalize and qualify that shape; it never treats any returned JSON as validated progress.

No personal account login, external issuer issuance, live relay publication, physical-iPad secure custody, or live-source timestamp/edition qualification was performed. Those are release acceptance gates, not successful test results. This implementation does not claim that the whole production integration is finished.

## Additional recovery decisions from implementation review

- Private synchronization rechecks peer enablement, owner, pairing-key invariants and independently configured issuer trust at execution/export. Reusing a source revision for different state is rejected; repeated exact packets are idempotent.
- Concurrent personal interpretations remain explicit conflicts. Keeping the current value can dismiss a reviewed stale conflict; selecting the incoming value cannot overwrite a newer local edit.
- Notebook edit journals keep a sequential CRDT branch for each `(notebook, block, mounted editor session)` tuple. This prevents both cross-notebook block-ID collisions and duplicate text when two still-mounted editor sessions alternate.
- Full text intents are acknowledged only after SQLite stores them. UTF-16 formatting ranges are validated before that acknowledgment. Heavy CRDT/history merging runs later and replays on reopening; malformed existing journals are retained rather than discarded.
- Independent process handles use an immediate SQLite transaction plus comparison with the observed pending intent/branch. A racing edit cannot silently erase a newer acknowledged intent.

Regression coverage now includes stale/forged/replayed sync approval, disabled devices, durable outbox reopening, duplicate/corrupt packets, corrupt content assets, concurrent character history, actual two-handle edit races, Unicode recovery, invalid formatting, and alternating editor sessions. These are deterministic local checks; they do not claim physical-device or account qualification.

## Decisions from the recovery and setup UX review

- Stage selected recovery files in memory, then validate the complete encrypted envelope in temporary native custody before saving. A failed or cancelled candidate does not replace the saved file or change the active identity. The review names the file and requires an explicit replacement action when recovery material already exists.
- Compare the validated identity against saved Connections settings, then recheck those settings and the saved recovery file immediately before committing. A concurrent change requires a fresh review. After successful replacement, clear the passphrase and lock the active identity; a normal unlock is a separate step.
- Keep unfinished device-pairing fields in the authorization coordinator's memory when navigating to Connections. The draft secret is never written to preferences or included in exports. The Sync checklist distinguishes saved recovery presence from an unlocked matching identity.
- Validate all optional access-token and header inputs before writing Connections settings. Settings and Keychain are separate stores, so a secure-store failure reports the partial result explicitly and retains each unsaved input for retry.
- Treat explicit file-picker and consent cancellation as normal navigation. Expired approvals and genuine failures retain actionable error messages.

`bash scripts/test-recovery.sh` exercises the Swift recovery and connection-save workflows with injected in-memory storage and warnings treated as errors. The native `recovery_validation` test uses the existing public synthetic encrypted vector to verify that candidate validation leaves live custody unchanged. These checks do not claim live Keychain, physical-device, or unlocked-screen UI acceptance.

## Completion-audit corrections

- Add a portable audio/ebook matching contract, consumed by Rust, native Swift and WASM, rather than leaving every observation permanently unmatched. Candidate evidence uses namespaced ebook identifiers or normalized title/author metadata. Conflicting languages or titles stay visible, and the reader must select the edition and reading pass explicitly. Confirmed association never promises audio-to-text synchronization.
- Preserve optional source metadata in progress observations and character-history snapshots. Old records omit the new field when round-tripped. The original source update time and audio milliseconds remain unchanged by matching.
- Respect companion capabilities in the app and server. Expose account renewal only when an installed adapter advertises it, and accept success only through its explicit renewal result. No Amazon login or renewal implementation is fabricated by this delegation.
- Interpret bounded machine error codes into useful recovery steps without echoing raw remote bodies. Missing adapter, expired pairing, unsupported capability and failed renewal have distinct explanations.
- Classify absent live source adapters as missing implementations, not simply absent test credentials. The current native Audible diagnostic also lacks a qualified source-response normalizer. Building and exercising an actual provider login/renewal/normalization implementation remains necessary before the live integration can be called complete.

## Issuer producer audit

The audit initially found an absent producer for the documented `booknook.credential-request.v1` HTTP request. Supplying real keys or an existing issuer URL alone could not fill that implementation gap. The optional [Book Nook reference issuer](../../services/castalia-issuer/README.md) now implements this endpoint using the existing native consumer and exact generic Castalia contract.

The inspected Wallet `ff8de6d` contract explicitly owns generic verification and custody, not application issuance or policy. The inspected secS source at `Devgraph/worktrees/secS-magik/web-sdk/server/src/devgraph_work_v2.rs` has an actual `issue_credential` producer, but it parses closed Devgraph Work requests, derives a Devgraph actor, checks Work policy grants, and signs independently derived Devgraph request bytes and disclosure. Its CLI also fixes the owner-private Devgraph authority configuration. An HTTP wrapper around that CLI would not make it a Book Nook issuer. No upstream services, grants, trust files, or keys were modified during this audit.

The new provider preserves the existing Castalia credential and presentation signature domains while adding an explicitly configured Book Nook policy adapter. It independently admits holder, caller, audience, exact action, policy digest, disclosure title/limits and validity; uses an operator-supplied signing key; and fails closed without grants. The request sends the payload digest, not the payload, so the issuer cannot claim it inspected detailed notebook or social content. Holder consent and receiver-side validation remain separate requirements. Real operator configuration, trust review and deployment remain qualification gates.

The issuer reads its current private configuration and supplied key for every request through descriptor-relative file handles. Symlink paths, hardlinks, key mismatch and nonprivate files are rejected; no authority is provisioned automatically. The HTTP wrapper requires bearer access bound to a configured holder and caller, rejects browser-origin requests, and returns fixed bounded errors. Tests exercise the actual executable and HTTP server with synthetic material, then native custody approval and independent receiver verification. No real issuer or user key was opened.

## Optional Audible adapter boundary

An additional opt-in executable can implement the companion's source protocol without adding Amazon account credentials to the notebook or native app binary. If an implementation uses the upstream `audible` Python package, its AGPL-3.0 license needs its own recorded distribution review; a separate process is not by itself a license exemption. No such dependency or implementation is bundled in this build.

The proposed account ceremony begins in Book Nook: choose marketplace, review the virtual-device registration effect, open Amazon's external login, and return the final authorization URL to a bounded secret field. A one-use, expiring adapter session must bind the PKCE verifier and marketplace, retain device credentials securely only after success, and discard or cancel pending authorization material. This requires an explicit completion/cancellation contract beyond the current authorization-URL operation. The external-browser return flow is described in the [upstream authorization documentation](https://audible.readthedocs.io/en/latest/auth/authorization.html); registration and renewal effects are described in the [device documentation](https://audible.readthedocs.io/en/latest/auth/register.html).

Live position normalization remains a separate gate after login. The [endpoint documentation](https://audible.readthedocs.io/en/latest/misc/external_api.html) does not qualify a response timestamp shape. An adapter must demonstrate the actual source-update semantics before advertising usable position observations. A successful login, fetch time, or audiobook percentage must not be substituted for that evidence.

## Optional Audible account completion and real source path (completion audit)

- Implemented `services/optional-audible-adapter` as a separately installed **AGPL-3.0-only** distribution. Exact upstream `audible==0.10.0` package metadata specifies AGPL-3.0-only. It is imported only by this optional Python process; no native/SDK dependency changed. Process boundaries are not asserted to remove licensing obligations. The adapter includes AGPL text, upstream MIT schema notice, a hashed macOS/Python 3.12 lock and a 21-package runtime inventory.
- Upstream external-login source `login.py` supplies the actual S256 URL/verifier/serial construction; `register.register` and `Authenticator` supply real registration, force-refresh and current-device deregistration. Browser MFA stays with Amazon. Completion validates the exact marketplace Amazon `/ap/maplanding` origin/path, rejects duplicate code parameters, and requires explicit virtual-device consent. The UI states the registration identifies as Audible for iPhone and appears in Amazon’s device list. No passwords, OTPs or DRM operations are implemented.
- Additive companion operations `account.authorize.complete`, `.cancel`, `account.disconnect`, `account.registration.reset`, and `audible.positions.probe` preserve the old URL-only login response and legacy provider parameters. New adapters receive a server-derived paired-device digest. Ten-minute one-use PKCE sessions and credentials use a whitelisted native OS keyring; plaintext/chained fallback stores are rejected. A private process lock serializes concurrent completion. An uncertain registration is never automatically retried. App-controlled reset requires explicit Amazon-device review and refuses saved credentials, a missing uncertainty marker, or another paired device.
- Found primary schema evidence beyond the original Python endpoint list: [`moifort/audible-api-ts` commit `a88fc1cf589184a3ca44c4e095c838745627c4a8`](https://github.com/moifort/audible-api-ts/tree/a88fc1cf589184a3ca44c4e095c838745627c4a8), `src/schemas.ts`, `src/library.ts`, unit and credential-gated integration tests. It specifies `asin_last_position_heard_annots`, `last_position_heard.status`, integer `position_ms`, and UTC `last_updated`, with 25-ASIN batches. The original Python normalizer uses those observed-contract fields and preserves stale source time separately from fetch time; no value is manufactured when evidence is missing. Duplicate/unrequested ASINs, invalid/future times and unknown statuses fail closed. Optional catalog title/authors/language use exact Rust UTF-8/control limits; failed metadata reads leave valid positions intact. Ebook identifiers remain empty rather than relabeling the audiobook ASIN.
- Kindle evidence remains insufficient for a live-library implementation: Amazon's [official Data Portability scopes](https://developer.amazon.com/docs/amazon-data-portability/available-scopes.html) describe digital order items and Kindle activity, but the inspected order-item schema lacks a Kindle ASIN/content classification and includes non-book examples. The [service setup](https://developer.amazon.com/docs/amazon-data-portability/overview.html) requires a registered/assessed/allowlisted developer configuration. Treating arbitrary order titles or activity identifiers as a purchased Kindle library would invent a catalog contract. Therefore Kindle live catalog/login is an explicit implementation gap; existing selected XML/JSON metadata imports remain functional.
- Verification: **16/16 adapter tests passed**, including real pinned upstream PKCE/register/refresh/deregister serialization and RSA-signed client requests with synthetic HTTP transport; **6/6 companion tests passed**, including actual loopback HTTP and real subprocesses for paired-device binding, one-use completion, cancel, renew, disconnect, uncertainty reset, and secret-safe errors. Source parser checks for modified Swift files passed. No real Amazon account, OS-keyring credential write, or live account/browser acceptance was performed. The new adapter always reports `qualified:false`; live account registration, MFA, refresh, response accuracy and native completion UX remain acceptance work. Full Apple builds are being coordinated by the reading workstream.
