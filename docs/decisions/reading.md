# Reading and notebook decisions

These decisions were made autonomously under the instruction to continue implementation and leave a reviewable log. They concern the native reader and TextKit notebook. No credentials, app data, or active simulator session were used for these tests.

| Decision | Reason and behavior |
| --- | --- |
| Store EPUB ink in document CSS coordinates. | WKWebView measures its actual `visualViewport`, and the native overlay converts view points using those measurements. Scrolling and zooming change presentation, not saved stroke coordinates. Both portable points and PKDrawing are saved in the canonical space. |
| Anchor each completed EPUB stroke to measured text geometry. | The bridge finds the nearest text run and stores exact quote/prefix/suffix plus line rectangles. A rigid translation is safe. Changed wrapping, line size, missing text, or duplicate text retains a visible marker and original context instead of guessing. Rotation or font changes that preserve the geometry keep placement; those that reflow the text show the marker. |
| Preserve legacy viewport ink without pretending it is relocatable. | Earlier annotations without document geometry remain in the saved annotation list. They are identified as needing their original context, and are not guessed onto a new layout. |
| Keep saved ink separate from the active Pencil stroke. | Finger input can scroll WKWebView between strokes while Pencil input enters the transparent capture layer. During an active stroke, reader scrolling and pinch are suspended to prevent a moving coordinate frame. Completed strokes wait for local save acknowledgement before being discarded from pending capture. Ink is visible even when the markup toggle is off. Pending capture failures retain the drawing and display an error. |
| Use PDFKit page coordinates and its conversion APIs. | PDF highlights retain per-line rectangles. Ink uses PDFKit-measured coordinate basis points, including page rotation and crop-box offsets, rather than a guessed top-left transform. The exact asset fingerprint isolates editions. Rendering annotations does not modify the imported PDF bytes. |
| Render portable ink on both platforms. | macOS renders iPad EPUB ink as SVG paths and PDF ink as PDFKit annotations. PKDrawing remains available for fidelity on iPad; SDK-created portable-only ink falls back to SVG there. PDFKit uses portable strokes regardless of whether Apple data exists. Coordinates, widths, colors, pressure, and timestamps remain portable. The portable display uses a constant stroke width; pressure samples are retained, not discarded. |
| Keep book-authored scripts disabled. | Only Book Nook’s small injected reader bridge runs. Native network rules block remote assets. The headless WebKit test verifies book scripts cannot execute while the trusted bridge can. |
| Preserve TextKit composition and native undo. | Marked IME text is not sent as a committed edit. Formatting does not interrupt composition. End-editing and dismantle callbacks capture committed changes; unchanged callbacks do not create extra saves. Cached snapshots avoid rescanning attributes on every unrelated SwiftUI update. |
| Give the active native editor ownership of text and selection. | Live QA found that delayed SwiftUI/autosave snapshots could replace newer typing and move the caret. After the first local edit, active TextKit ignores external snapshots; focus loss permits refresh, while explicit history/sync actions drain and remount. A real AppKit regression interleaves stale snapshots with rapid ASCII/Unicode input and asserts every character and caret location. The test fails without the guard. Isolated macOS app QA subsequently confirmed exact rapid ASCII input, undo/redo, Unicode paste, and notebook-history restoration. Automated Unicode keystroke injection was unreliable; direct TextKit Unicode tests and paste verification are distinguished from physical IME qualification. |
| Make notebook history directly recoverable. | Every thought has a history sheet with formatted previews. Restoring a selected version creates a new rich-text revision and retains the original history; it merges against the reviewed base so unseen replica edits are preserved. Local typing is drained before preview or restoration. |
| Use stable characters across reading passes. | The character selector reuses a book’s existing literary character. Attaching it creates a new card with its own history. A relationship editor stores references to other literary characters, never Rolodex identities. |
| Capture and restore actual source locations. | EPUB positions are exact contextual passages and PDF positions are page numbers. Reader observations are deduplicated; DOM position measurement is throttled with a trailing update. Reopening a reader restores only a matching source location. Font-size controls trigger measured reflow. History displays stored observation times and alignment status, without equating audiobook and ebook percentages. |
| Keep the local edit branch separate from the merged document. | A review found that deriving every edit from the freshest merged state could erase unseen remote text. Passing the same stale base for every keystroke could instead duplicate local inserts. The UI now supplies an editor session and its originally displayed base; the root implementation owns the durable, sequential local branch journal and remounts editors only after draining and explicitly accepting synchronization. |

## UX round 1 — draft safety and recoverable interpretation

The reader/writer review found three concrete usability defects: card and note-share sheets dismissed after failed persistence, character history omitted most saved interpretation fields, and same-day reading passes had identical labels. The accepted changes:

- A shared draft-commit state keeps the sheet and entered values intact until a throwing persistence call succeeds, disables duplicate submissions, and shows an inline retryable error. This covers attaching characters, saving interpretations, and preparing selected-note drafts. Errors use the app's readable native-error formatter.
- Character history now includes description, traits, relationships with character names, observations, open questions, full supporting passages, reader attribution, and source positions. Empty fields are explicitly identified. The history button has an accessible character name and version count.
- Reading passes are ordered by start time, numbered, include date/time, and identify the current pass with a checkmark. Starting a pass selects the newly created notebook explicitly rather than relying on a timestamp tie.
- The character editor scrolls while its Cancel/Save controls stay outside the scrolling form. This is intended to preserve access while the iPad keyboard is shown; physical/live keyboard-layout acceptance remains pending.

`tests/NotebookWorkflowTests.swift` passes for a rejected save retaining its draft, duplicate-save suppression during persistence, successful retry acknowledgement, complete history fields, untruncated Unicode supporting passages, and independence of earlier interpretations. This is a headless state/projection test. The Mac was locked during this review, so no new live UI acceptance is claimed for these changes.

## D085 — measure the displayed ink version during a stroke (2026-10-15)

The automatic notebook paper keeps TextKit and PencilKit mounted together. A source review found that its page measurement used the newest model head's dimensions while the ink host intentionally deferred applying that head during an active stroke. An incoming version with a different canvas size could therefore change the visible drawing's scale before it became the displayed version.

Page height and width conversion now use the native host's applied logical canvas size. The existing immutable save path still captures the displayed version as the parent; an unseen incoming head remains independently recoverable. This changes neither stored coordinates nor schemas, and does not turn freeform ink into a prose anchor.

`tests/AutomaticNotebookPageAcceptance.swift` delivers a version with twice the width and three times the height during an actual native canvas delegate session. It requires the displayed bounds/transform to stay unchanged, then requires the completed drawing's exact native bytes, original dimensions and displayed parent while retaining the incoming head. Full iOS source typechecking and the post-fix synthetic native preflight on iOS 18.6 Simulator pass. The source-review race was not reproduced by executing a pre-fix negative control; preserved old source provides review evidence, not a measured failing run. No physical Pencil, palm rejection or simultaneous hardware resize claim follows from these framework checks. Prior source/test/receipt bytes are preserved in `work/quiet-writing-desk-2026-10-15/before-incoming-ink-geometry-fix`; current source hashes and checks are in that work directory's `notebook-source-checks.json`.


## Final plan audit — durable pending ink and cancellable recognition (2026-10-15)

Completed notebook and reader captures now stage immutable app-private records before asynchronous native save or passage resolution. A serial filesystem actor writes a complete 0600 file, synchronizes it, publishes it with an atomic no-replace hard link, and synchronizes the directory. Exact-existing-record retries repeat both barriers. Stable capture IDs, notebook parent links and reader predecessor links preserve identity and ordering even if the wall clock changes. Removal requires the exact original record and follows native SQLite acknowledgment. No public schema or archive envelope changed.

Recovery promotes a complete interrupted temporary record, but retains malformed/partial/conflicting originals with a visible error. Unsupported recovery cannot silently become a successful portable backup. Reader captures retain exact pass, edition, asset/resource and layout context; they never acquire a substitute quote or a different book's location. A durable unresolved capture permits ordinary navigation and side swapping; export still requires explicit finalization. A contextual recovery list makes pending markup reachable even if its old asset is no longer the displayed reader. Before the initial recovery acknowledgment, the drawing remains vulnerable to process termination; no power-loss guarantee is claimed.

`tests/InkRecoveryAcceptance.swift` and opt-in `scripts/test-ink-recovery.py` exercise actual linked app/native persistence. The final child is killed with SIGKILL after four journal acknowledgments while one anchor is suspended and notebook persistence is failing. The verifier reopens, checks ordered original/erasure versions, IDs, parents, timestamps, native bytes and reader context, explicitly finalizes unplaced markup, exports, and reopens again. The first actual recovery run exposed an integer-to-Double rectangle decoding error; the final decoder converts numeric coordinates explicitly, rejects Boolean/nonfinite/invalid rectangles, and retains rejected records. The final run passes with no source drift. Injected directory-barrier interruption also proves that an existing-record retry cannot skip acknowledgment work; stale removal and ID collisions are rejected.

Transcription now uses a retained request controller. Stop/Cancel invalidates its generation and forwards cancellation to Vision; a late result cannot overwrite manual edits or affect a later request. Cancellation never mutates the original ink or typed prose. A committed transcript save remains a separate operation with visible failure and retained review text. The actual controller/native workflow passes cancellation, late completion, failed-save retry and exact-version persistence.

The focused UIKit automatic-paper acceptance uses actual mounted TextKit/PencilKit instances for Unicode insertion, undo/redo, marked-text protection and commit, independent synthetic ink undo, return to typing and bounded long-section measurement. Real native delegate callbacks are required; there is no manual delegate fallback. A long section that exceeds the logical canvas shows a measured continuation control in an excluded prose gap; it neither overwrites original ink nor silently maps Pencil input beyond the canvas. The unchanged test passed on the isolated iOS 18.6 Simulator. Synthetic undo registration and marked-text APIs do not qualify a physical keyboard, IME interaction, Pencil contact, pressure/tilt or palm behavior.
