# Note origin and whiteboard contract

The opt-in note contract uses `booknook.archive.v3` / ontology `0.3.0`. Existing v1 typed documents and v2 ink documents remain readable. Original commands that omit every new optional field retain their original behavior, including their archive version; issued conformance fixtures remain executable. Older readers reject v3 instead of silently discarding note context or whiteboard coordinates.

A stable `Block` may contain `note: {schema: "booknook.note.v1", face, created}`. `face` is `text` or `whiteboard`; changing it leaves the block's position in the notebook array, CRDT prose, card attachments, ink versions and transcriptions intact. `set_note_face` selects the face and creates no drawing version. A blank block opened automatically has no creation date. Switching that blank block's face creates a `pending` origin with a null date.

`created` contains `source`, nullable `at`, `reader`, `pass_id`, `positions`, and `position_observations`. A modern first meaningful input or explicit Add note records its original context once. Surviving legacy history yields `history_fallback`, which is evidence of a historical edit, not a claim about when the note was first created. Populated legacy notes without history use `unknown`; their date remains null. Modern edits never relabel such legacy origins with today's date.

Inputs may carry `capture_context: {pass_id, positions, position_observations}`. These snapshots validate against the note's pass and book but need not equal the latest position row: a source can overwrite an observation ID after the gesture or typing began. Omission on the existing ink API preserves its earlier commit-time capture behavior. Native UI consumers supply explicit captured context, including an explicit empty snapshot when no source position is known.

Text, ink and character attachment commands additionally accept `note_creation: {at, capture_context}`. A client shares the first meaningful input intent across these surfaces until persisted; this is separate from each latest edit or drawing's `at` and capture context. This matters when text is coalesced, erased before flush, or a drawing commits before pending text. The native text journal retains the first creation intent across coalescing and restart. It rejects a changed explicit pending creation intent, and commits an older legacy pending edit before deriving a modern fallback. `add_block` accepts optional `capture_context` and `face` together to create an explicitly dated blank note atomically. Legacy Rust `Command` constructors now supply `None` for the new optional fields; the serialized JSON contract remains backward compatible.

Ink versions optionally carry `canvas_space: {kind: "whiteboard", origin_x, origin_y}`. Width and height describe an expandable world rectangle, not a fixed page labeled infinite. Both near and far edges must stay within ±1,000,000 logical units; dimensions must be finite and between 1 and 2,000,000. Missing `canvas_space` retains the earlier finite 1–16,384 page dimensions. Stroke points remain absolute logical coordinates bounded by ±1,000,000. Panning, zooming or growing the visible world does not transform stored strokes, original native drawing data, or earlier versions. Only a new drawing snapshot changes drawing history. Transcriptions still reference an exact immutable ink version and never replace it.

Reconciliation unions immutable drawing history and retains existing block order. A common base resolves a one-sided face change. Differing recorded creation contexts, or face changes with no usable common base, return an explicit conflict instead of selecting a timestamp winner; the callers retain both replicas for review. An older replica cannot remove note metadata or downgrade a v3 archive.

[Ontology discovery](../ontology/discovery.json) advertises the new release while preserving all issued v0.1.0/v0.2.0 and provider/portable v1 files. The complete portable envelope still uses `booknook.portable-export.v1`; [portable schema edition 2](../ontology/portable/v2/manifest.json) describes its expanded State contract. The envelope's asset checks, original signed JSON strings, social records, and settings/secret exclusions are unchanged.
