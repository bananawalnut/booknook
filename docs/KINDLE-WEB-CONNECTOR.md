# Kindle US web catalog connector

Connections → Kindle library → **Sign in to Kindle US and import catalog…** opens an isolated, temporary Amazon sign-in sheet. The reader completes sign-in and any Amazon verification themselves, then explicitly chooses **Import catalog**. The implementation is available; **live Amazon sign-in, endpoint compatibility, catalog coverage and regional behavior remain unqualified**. No account was used to develop or test it. The existing file/companion import remains available.

Only the US website is implemented. The flow does not reuse the Audible marketplace, silently map a non-US account to the US, or promise that Amazon will accept embedded WebKit sign-in. If verification requires an unsupported origin or the internal endpoint is unavailable, the sheet reports failure and the reader can close it or use a catalog file.

## Source evidence and scope

The primary implementation reference is MIT-licensed [swift-kindle at 63be4d46c53afadf3b57280139e326f8b3d98cde](https://github.com/natikgadzhi/swift-kindle/tree/63be4d46c53afadf3b57280139e326f8b3d98cde), dated 2026-04-12. Its [endpoint definitions](https://github.com/natikgadzhi/swift-kindle/blob/63be4d46c53afadf3b57280139e326f8b3d98cde/Sources/KindleAPI/KindleEndpoint.swift) changed the login return destination from the discontinued `/kindle-library` landing page to `/notebook`. Its JSON catalog still uses `/kindle-library/search`. The Notebook page is used only as a login destination; its annotated-books HTML collection is not substituted for a catalog.

The [catalog implementation](https://github.com/natikgadzhi/swift-kindle/blob/63be4d46c53afadf3b57280139e326f8b3d98cde/Sources/KindleAPI/KindleAPI.swift) and [response model](https://github.com/natikgadzhi/swift-kindle/blob/63be4d46c53afadf3b57280139e326f8b3d98cde/Sources/KindleAPI/Models/KindleJSONBook.swift) establish the request parameters and optional opaque pagination token. The upstream README explicitly describes an unofficial internal API and does not supply a complete authentication lifecycle. Book Nook adds the native temporary-session boundary; that addition has synthetic acceptance, not proof that current Amazon sign-in accepts it.

As corroborating historical evidence, MIT [Xetera/kindle-api at dc34acf607783aa3a64a9c52ff72bfdbaefcd12b](https://github.com/Xetera/kindle-api/tree/dc34acf607783aa3a64a9c52ff72bfdbaefcd12b) implements the same JSON catalog/token flow. Its external TLS-fingerprinting proxy and manual cookie extraction are not used. AGPL [mkb79/kindle at 98c06a7073082cb0516a9359952cd1c4e9a26cdb](https://github.com/mkb79/kindle/tree/98c06a7073082cb0516a9359952cd1c4e9a26cdb) was inspected as an alternative, but its single `item_count=1000` metadata request does not establish full pagination; no code, dependency, virtual-device registration or DRM functionality from that project is included.

## Data and authentication boundaries

- A new `WKWebsiteDataStore.nonPersistent()` and web view belong to each sheet. No existing browser profile, cookies, credentials or user cache is discovered. Book Nook never enumerates the production session's cookies, reads password fields, extracts auth tokens, or copies them into Keychain, UserDefaults, the companion or an export. Amazon's own sign-in form receives the entered credentials. Close and successful import clear the temporary website store; the sheet releases it.
- Top-level and frame navigation accepts HTTPS on exactly `www.amazon.com`, `amazon.com` and `read.amazon.com`, with no URL credentials or nonstandard port. New windows and other navigation destinations are rejected. Amazon page subresources are managed normally by WebKit; this is not an assertion that every first-party page uses only those three resource hosts.
- Only an explicit import invokes the fixed fetch script in a private WebKit content world. It requires the current document and catalog request to have the exact `https://read.amazon.com` origin. Cookies stay in WebKit and are sent with `credentials: same-origin`; redirects fail. There is no TLS override, device registration, background polling, external proxy, script message handler or raw response logging.
- The temporary source is represented by existing `castalia.provider-connection.v1`, provider `com.amazon.kindle`, capability `kindle.catalog`, an opaque generated local connection ID and `credential:null`. This does not attest identity or grant authority. Its reference is recorded by the existing `import_kindle_from_connection` command, without replacing the selected companion registry. Closing requires another sign-in; the reference does not make auth portable.

## Enumeration and import

Requests use `query=`, `libraryType=BOOKS`, `sortType=recency`, `querySize=50`, adding the returned opaque `paginationToken` through URL encoding. Missing/null token terminates enumeration. Empty, malformed or repeated tokens fail; so does a duplicate ASIN with differing metadata across pages. Identical duplicate records are deduplicated.

Bounds are 2 MiB per page, 32 MiB total, 200 pages, 10,000 unique titles, 120 seconds for the collection and 15 seconds per request, enforced by both a JavaScript abort timer and a native one-shot completion deadline. Native cancellation/deadline also completes when JavaScript ignores abort; late callbacks cannot complete a second time. The overall deadline is checked before and after each request; an in-flight request can finish up to 15 seconds later, but its result is rejected. Content length and actual streamed bytes are checked; invalid UTF-8, HTML/login responses, HTTP errors and unexpected JSON shapes fail. Hitting a limit does not silently import a partial library.

Only validated ASIN, title and author strings enter `booknook.kindle-catalog.v1`. `position` and `observed_at` are explicitly null. Percentage, recency, fetch time, book URLs and unrelated response fields are not turned into reading evidence or content access. Returned rows are not labeled as purchases: the endpoint may include other library items. “Endpoint finished” means only that its pagination ended; there is no independently verified total, snapshot consistency or full purchase-history claim. Missing titles never trigger deletions.

The entire normalized result is committed through the existing Rust import command after enumeration and a final cancellation check. Failure before commit leaves the library unchanged. If an already-started SQLite commit succeeds during cancellation, its durable snapshot is accepted without replacing a newer visible revision. Repeated imports retain existing private edits through the shared reconciliation rules.

## Validation and outstanding qualification

Run `bash scripts/test-kindle-web.sh` on macOS after building the native bridge. The test links the actual app and SQLite core. It covers pagination and failure bounds, private-edit preservation, cancellation before/after commit, reopen, and actual WebKit nonpersistent stores/content worlds with in-memory synthetic responses. It does not load Amazon, enter credentials, modify an account, use a physical device or exercise a live provider.

Release qualification still needs a reader-selected US Amazon account session, actual successful and expired sign-in behavior, comparison of the returned enumeration against that account's expected titles, and an account with enough titles to exercise real pagination. The parser/transport must be updated from actual upstream evidence if Amazon responds differently; do not invent auth tokens, alternate APIs, timestamp semantics or non-US routing to hide failure.

The source acknowledgement and complete upstream MIT notice are bundled in [KindleWebSourceNotice.txt](../apps/apple/Resources/KindleWebSourceNotice.txt). The [source inventory](kindle-web-source-inventory.json) adds no Cargo, npm, Swift Package Manager or Python dependency.
